A:

Вот полный набор артефактов и инструкций для Этапа 0 (PHP 8.4 + Symfony LTS, React, dev‑compose). Я ничего не писал на диск — ниже готовые структуры и содержимое файлов, чтобы вы могли вставить их вручную или дать добро на запись.

#### Структура папок

- `backend/` — Symfony (skeleton)
- `frontend/` — React (Vite)
- `deploy/` — инфраструктура (nginx, php)

docker-compose.yml

```yaml
version: "3.9"
services:
  nginx:
    image: nginx:1.27-alpine
    ports:
      - "80:80"
    volumes:
      - ./deploy/nginx/default.conf:/etc/nginx/conf.d/default.conf:ro
      - ./backend/public:/var/www/public:ro
    depends_on:
      - php
      - frontend

  php:
    build:
      context: ./deploy/php
    volumes:
      - ./backend:/var/www
    environment:
      APP_ENV: dev
      DATABASE_URL: "postgresql://app:app@postgres:5432/app?serverVersion=16&charset=utf8"

  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: app
      POSTGRES_USER: app
      POSTGRES_PASSWORD: app
    ports:
      - "5432:5432"
    volumes:
      - db_data:/var/lib/postgresql/data

    image: node:20-alpine

    ports:
      - "5173:5173"
```

deploy/nginx/default.conf

```nginx
server {
  listen 80;
  server_name localhost;

  root /var/www/public;

  location ^~ /api/ {
    try_files $uri /index.php$is_args$args;
  }

  location ~ ^/index\.php(/|$) {
    fastcgi_pass php:9000;
    fastcgi_split_path_info ^(.+\.php)(/.*)$;
    include fastcgi_params;
    fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    fastcgi_param DOCUMENT_ROOT $document_root;
    internal;
  }

  location ~ \.php$ {
    return 404;
  }

  location / {
    proxy_pass http://frontend:5173;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  }
}
```

#### Команды (развернуть и проверить)

1. Создать Symfony skeleton (LTS 6.4) внутри контейнера:

```bash
docker compose build
docker compose run --rm php composer create-project symfony/skeleton:"6.4.*" /var/www
```

2. Запуск:

```bash
docker compose up -d
```

3. Проверка:

```bash
curl http://localhost/api/health
```

Ожидаемый ответ: {"status":"ok"}

#### Риски и как избежать

- CORS: при доступе через `http://localhost` все идет через nginx, фронт и API на одном хосте — CORS не нужен; если будете ходить напрямую на `localhost (line 5173)`, появится CORS, решайте проксированием через nginx или Vite proxy.

- Пути `/api/*`: важно, что nginx `location ^~ /api/` делает try_files к index.php — иначе Symfony роуты не отработают.

- Volumes: bind‑mount `./backend` и `./frontend` перетрет `vendor/` и `node_modules`, если они лежат в контейнере. В dev допустимо, но можно добавить named volumes для `backend/vendor` и `frontend/node_modules`, чтобы не терять зависимости и ускорить запуск.

- PHP 8.4 образ: если `php:8.4-fpm` недоступен на вашей машине (зависит от версии Docker), временно используйте `php:8.4-rc-fpm` или `php:8.3-fpm` и вернитесь к 8.4, когда стабильный образ станет доступен.
